## It runs with no accounts

You don't need a backend, a Firebase project or an Apple Developer team to build the app, run it or put it on a
phone. Development builds serve sample data from a mock backend inside the app, and every service falls back
when its account is missing:

- **No backend:** the mock backend answers sign-in (Apple and Google included), the feed and every other
  request.
- **No Firebase:** crash reports and analytics go to the console, feature flags use their defaults, and
  notifications stay local.
- **No Apple or Google account:** debug builds run on simulators and emulators, and a demo APK installs on any
  Android phone.

When you're ready, [Going live](/production/going-live/) lists what to add and what each step switches on.

## Writes that work offline

Every write in the app picks one of four behaviours, so users always know what happened to what they did.

| Pattern | What the user sees                                                   | Use it for                 |
| ------- | -------------------------------------------------------------------- | -------------------------- |
| A       | The change appears at once and syncs in the background               | Low-stakes toggles         |
| B       | The change appears at once, marked "Waiting to sync" until it's sent | Likes, comments, edits     |
| C       | The form is disabled while offline, with the reason                  | Sign-in, payments          |
| D       | The screen is replaced by an offline message                         | Account deletion, checkout |

Writes queued with A or B survive closing the app and are sent in order when the connection returns. An offline
banner sits under the header while the phone is offline. [How to choose and use a pattern](/build/offline/)

## Built for AI agents

The rules your team follows are written down where coding agents read them, and the linter checks the result.

- **[AGENTS.md](/build/project-rules/)** holds the commands, architecture rules and conventions. Claude Code,
  Cursor and Copilot are pointed at it.
- **Skills** for adding a feature, a screen or an endpoint run the generators, then walk the agent through
  fields, offline behaviour, strings and tests. Callstack's React Native skills are included and pinned.
- **Accessible by default:** screens use ARIA roles and labels, so agents that drive the app on a simulator
  read the screen as text instead of guessing from screenshots.

[How agents work with the template](/build/ai-agents/)

## Is this for you?

<CardGrid>
  <Card title="A good fit if you" icon="approve-check-circle">

    - want to own `ios/` and `android/` and see every native change
    - build an app that has to work offline and keep users' writes
    - work in a team, or with AI agents, and want the rules checked
    - want to start from working code and remove what you don't need

  </Card>
  <Card title="Not a fit if you" icon="warning">

    - want Expo's managed workflow or Expo Go: start from an Expo template instead
    - need a backend: this is the app side only, with a mock backend to build against
    - want a UI kit: it has about 15 primitives, not a full component library

  </Card>
</CardGrid>

## Get started

<Steps>

1. Create the app. It checks your tools first, then installs everything and sets the bundle id
   (other ways, with the React Native CLI or GitHub's template: [Quick start](/start-here/quick-start/#or-step-by-step)):

   ```bash
   npx create-bareship Acme
   ```

2. Start an emulator or simulator, then run the app and sign in with `demo@example.com` / `password123`:

   ```bash
   cd Acme
   pnpm android          # or: pnpm ios
   ```

3. When you start on your own screens, remove the demo and add your first feature:

   ```bash
   pnpm strip-examples
   pnpm gen feature orders
   ```

</Steps>

## Questions

<details>
<summary>Do I need a backend to start?</summary>

No. Development builds use a mock backend inside the app. When your API is ready, set `API_URL` and
`API_MOCKS=false` in the environment's `.env` file. [Use your API](/production/going-live/#use-your-api)

</details>

<details>
<summary>Do I need Firebase?</summary>

No. Without a Firebase file the app logs crashes and analytics to the console, uses default feature flags and
shows notifications locally. Add the file when you want the real services.

</details>

<details>
<summary>Which platforms and versions does it support?</summary>

iOS 15.1 and later, and Android 7.0 (API 24) and later, on React Native 0.87 with the New Architecture.
[Version matrix](/reference/version-matrix/)

</details>

<details>
<summary>Can I move to Expo later?</summary>

Every change to `ios/` and `android/` is listed with its Expo equivalent in
[Native changes](/production/native-changes/), and native libraries sit behind small interfaces, so the app code
doesn't depend on how the native side is built.

</details>

<details>
<summary>How do I get template updates into my app?</summary>

Your app owns its copy of the code, so nothing updates on its own. Each version is published to
[npm](https://www.npmjs.com/package/bareship) and listed in the [changelog](/reference/changelog/); copy the
changes you want.

</details>

<details>
<summary>What does it cost?</summary>

Nothing. It's open source under the MIT license.

</details>
